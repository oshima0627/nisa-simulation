# NISAシミュレーション Webサイト 要件定義書

- 版: v1.1
- 作成日: 2026-07-28
- ステータス: レビュー中
- 公開URL: https://nisa.nexeed-lab.com（独自ドメイン、`nexeed-lab.com` のサブドメインを Vercel に割当）

---

## 1. 概要

### 1.1 目的

新NISA（2024年開始の制度）を対象とした資産形成シミュレーションWebサイトを開発・公開する。
単なる複利計算にとどまらず、**生涯非課税保有限度額（1,800万円・簿価管理）の消化状況の可視化**と、
**積立フェーズから取り崩しフェーズまでの一気通貫シミュレーション**を提供することで、
既存の量産型シミュレーターと差別化する。

### 1.2 ゴール

- 実際に一般ユーザーに使ってもらうこと（ポートフォリオ専用ではない）
- 「NISA シミュレーション」等の検索流入と、SNS・URL共有による拡散
- 投資初心者にも運用経験者にも価値がある、二層構造のUI

### 1.3 ターゲットユーザー

| ペルソナ | 状況 | 求めるもの |
|---|---|---|
| 初心者（メイン導線） | NISA未開設〜開設直後 | 「毎月◯円を◯年続けるとどうなるか」を最小の入力で直感的に |
| 運用中の人（詳細モード） | 既にNISAで運用中 | 現在の保有額・消化済み枠を反映した正確な試算、枠の使い切り時期、出口戦略 |

同一の計算エンジンを使い、**かんたんモード／詳細モード**のトグルで両者に対応する。
詳細モードの初期値をすべてゼロにするとかんたんモードと同一の結果になる設計とする。

## 2. 機能要件

### 2.1 リリースフェーズ

全機能を作ってから公開するのではなく、Phase 1 完成時点で公開し、以降は公開しながら拡張する。

| フェーズ | 含む機能 |
|---|---|
| **Phase 1（初回公開）** | F1 積立シミュレーション / F2 資産推移グラフ / F3 課税口座比較 / F4 非課税枠管理 / F9 URL共有・入力保存 |
| **Phase 2** | F5 目標額からの逆算 / F6 信託報酬の考慮 / F7 インフレ調整 |
| **Phase 3** | F8 取り崩し（出口戦略）シミュレーション |

### 2.2 機能一覧

#### F1. 積立シミュレーション

- 入力（かんたんモード）:
  - 毎月積立額（円、上限: 月30万円 = 年360万円）
  - 想定利回り（年率%、デフォルト 5%）
  - 積立期間（年、1〜50年）
- 入力（詳細モード、上記に追加）:
  - 現在のNISA評価額・元本（既に運用中の人向け）
  - 消化済み生涯枠（簿価ベース）
  - つみたて投資枠／成長投資枠の配分
  - ボーナス月の増額設定（年2回まで）
  - 現在年齢（取り崩しシミュレーションと連動）
- 出力: 最終評価額、投資元本合計、運用益合計

#### F2. 資産推移グラフ

- 元本と運用益の積み上げ面グラフ（年単位）
- ホバー/タップで各年の内訳（元本・運用益・評価額）を表示
- 生涯枠1,800万円に達し積立が停止する時点をグラフ上にマーカー表示

#### F3. 課税口座との比較（節税効果）

- 同一条件で特定口座（税率20.315%）で運用した場合の税引後受取額を併記
- 節税額（「NISAで◯◯円おトク」）を結果カードのサブ指標として表示
  ※結果カードの主役は**最終評価額**とする（§6参照）

#### F4. 非課税枠管理【差別化の中核】

- 年間投資枠: 合計360万円（つみたて投資枠120万円＋成長投資枠240万円）
- 生涯非課税保有限度額: 1,800万円（うち成長投資枠は1,200万円まで）を**簿価（取得価額）ベース**で管理
- 枠を使い切る年をシミュレーション結果に明示（例:「◯年◯月に生涯枠を使い切ります」）
- 枠消化状況のゲージUI（年間枠・生涯枠・成長投資枠内訳）
- 売却時の枠復活は**簿価分が翌年に復活**する仕様を正確に実装（Phase 3 の取り崩しと連動）

#### F5. 目標額からの逆算（Phase 2）

- 入力: 目標金額、期間、想定利回り → 出力: 必要な毎月積立額
- 逆算結果が年間投資枠（月30万円）を超える場合は、その旨と「達成可能な最短期間」を提示
- 閉形式解（年金終価係数の逆算）で算出し、月100円単位に切り上げ

#### F6. 信託報酬の考慮（Phase 2）

- 入力: 信託報酬（年率%、デフォルト 0.1%）
- 実質利回り = 想定利回り − 信託報酬 として計算（簡易控除方式。方式は画面上に注記）
- コストありなしの最終額差分を表示（低コストファンド選択の重要性の啓蒙）

#### F7. インフレ調整（Phase 2）

- 入力: 想定インフレ率（年率%、デフォルト 0%＝無効）
- 「名目」「実質（現在の貨幣価値換算）」の表示トグル
- 実質価値 = 名目価値 ÷ (1 + インフレ率)^経過年数

#### F8. 取り崩しシミュレーション（Phase 3）

- 入力: 取り崩し開始年齢（または積立終了からの年数）、取り崩し方式
  - 定額方式: 毎月◯円
  - 定率方式: 年◯%
- 出力:
  - 資産寿命（資産が尽きる年齢／尽きない場合はその旨）
  - 積立→据置→取り崩しの生涯キャッシュフローグラフ
  - 課税口座で同じ取り崩しを行った場合との比較（NISAは取り崩し時も非課税）
- 取り崩しによる生涯枠の翌年復活を反映（復活枠への再投資はv1では対象外とし、将来検討）

#### F9. URL共有・入力保存

- 入力条件をURLクエリパラメータにエンコードし、URLだけで結果を再現可能にする
- 「結果をシェア」ボタン（URLコピー、X/LINE共有）
- 直近の入力条件を localStorage に自動保存し、再訪時に復元
- サーバーへの個人データ送信は一切行わない

### 2.3 対象外（明示的スコープ外）

- アカウント登録・ログイン・サーバーサイドでのデータ保存
- モンテカルロ法等の確率的変動シミュレーション（将来検討）
- 特定の金融商品・銘柄の推奨、実在ファンドのデータ連携
- 旧NISA（一般NISA・つみたてNISA）からのロールオーバー計算
- iDeCo等の他制度との併用シミュレーション（将来検討）

## 3. 計算仕様

数値の信頼性がプロダクトの生命線であるため、計算仕様を明文化し、全ロジックにユニットテストを課す。

### 3.1 複利計算

- **月次複利、月利 = 年率 ÷ 12** を採用する（金融庁「つみたてシミュレーター」と同方式）
  - 理由: ユーザーが公的シミュレーターや他サイトと結果を突合したときに一致すること
- 積立は毎月末に入金し、当月から利息が付くものとする
- 計算はすべて円単位、最終表示は円単位（内部計算は浮動小数、表示時に四捨五入）

### 3.2 非課税枠（簿価管理）

- 生涯枠の消化は**取得価額（簿価）ベース**で累積する
- 年間投資枠（360万円）に達した月以降、その年は積立を停止し翌年1月に再開
- 生涯枠（1,800万円）に達した時点で以降の積立を自動停止し、運用のみ継続
- 売却時: 売却分の簿価（加重平均取得価額 × 売却口数比率）が**翌年1月**に生涯枠へ復活
  - 年間投資枠は復活しない（復活枠を使う場合も年間360万円の制限内）

### 3.3 課税口座比較

- 税率: 20.315%（所得税15% ＋ 復興特別所得税0.315% ＋ 住民税5%）を全期間一律で適用
  - 復興特別所得税の期限（2037年）は考慮しない（免責事項に注記）
- 課税は売却時（取り崩し時／最終時点評価）にのみ発生する簡易モデルとする（分配金再投資型を想定）

### 3.4 バリデーション

- 毎月積立額: 100円〜30万円（100円単位）
- 想定利回り: 0〜15%（0.1%刻み。10%超は警告表示「過去実績として楽観的な水準です」）
- 期間: 1〜50年
- 不正値・枠超過の入力はインラインエラーで即時フィードバック

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| レスポンシブ | モバイルファースト（想定流入の過半がスマホ）。375px〜対応 |
| パフォーマンス | Lighthouse Performance 90+ / 計算は全てクライアントサイドで即時（<16ms目標） |
| アクセシビリティ | WCAG 2.1 AA 準拠目標。グラフには数値テーブルの代替表示 |
| SEO | SSG によるメタ情報・構造化データ出力。用語解説コンテンツページを併設（※金融領域はYMYLのため上位表示は長期戦と認識する） |
| ドメイン | `nisa.nexeed-lab.com`（独自サブドメイン）。Vercel にカスタムドメインとして設定し、HTTPS は Vercel の自動証明書を利用 |
| ブラウザ | 直近2バージョンの Chrome / Safari / Edge / Firefox、iOS Safari |
| プライバシー | 入力データはサーバー送信しない。アクセス解析は Vercel Analytics（Cookieレス）のみ |
| 免責表示 | 「本シミュレーションは概算であり、将来の運用成果を保証するものではありません。投資助言ではありません」を**結果表示の直下**とフッターに常設 |

## 5. 技術スタック

すべて無料枠で運用可能な構成とする。

| レイヤ | 技術 | 理由 |
|---|---|---|
| フレームワーク | **Next.js（App Router）+ TypeScript** | SSGでSEO対応、Vercel無料デプロイ、エコシステム |
| スタイリング | Tailwind CSS | 開発速度、デザイン一貫性 |
| グラフ | Recharts | React親和性、積み上げ面グラフ・レスポンシブ対応 |
| 状態管理 | React標準（useState/useReducer）＋ URLSearchParams | 規模的に外部ライブラリ不要 |
| テスト | **Vitest**（計算ロジック）＋ Testing Library（UI）＋ Playwright（E2E、主要導線のみ） | 金額計算の正確性担保が最優先 |
| Lint/Format | ESLint + Prettier | 標準構成 |
| CI | GitHub Actions（lint / typecheck / test をPRごとに実行） | 無料枠 |
| ホスティング | Vercel（Hobbyプラン） | 無料、プレビューデプロイ |
| 解析 | Vercel Analytics | Cookieレス、無料枠 |

### 5.1 設計方針

- 計算ロジックは `src/lib/simulation/` に**UI非依存の純粋関数**として実装し、100%テストカバレッジを目標とする
- 入力状態 ⇔ URLクエリパラメータの双方向シリアライズ層を独立モジュール化
- 金額・率の型を明確化（円は整数、率は小数）し、単位バグを型レベルで防ぐ

```
src/
├── app/                # ルーティング・ページ
│   ├── page.tsx        # シミュレーター本体
│   └── guide/          # 用語解説・制度解説（SEOコンテンツ）
├── components/         # UIコンポーネント
├── lib/
│   ├── simulation/     # 計算エンジン（純粋関数・要テスト）
│   │   ├── accumulate.ts   # 積立計算
│   │   ├── quota.ts        # 非課税枠管理
│   │   ├── tax.ts          # 課税口座比較
│   │   ├── withdraw.ts     # 取り崩し（Phase 3）
│   │   └── reverse.ts      # 逆算（Phase 2）
│   └── share/          # URLパラメータのシリアライズ
└── constants/          # 制度定数（枠上限・税率）を一元管理
```

- 制度定数（年間枠360万円・生涯枠1,800万円・税率等）は `constants/` に集約し、**制度改正時に1ファイルの変更で追従できる**構造とする

## 6. 画面構成（Phase 1）

| 画面 | 内容 |
|---|---|
| トップ（シミュレーター） | 入力フォーム（かんたん/詳細トグル）→ 結果カード → 資産推移グラフ → 枠消化ゲージ → 共有ボタン → 免責 |
| 制度解説ページ群 | 新NISAの仕組み・用語解説（SEO用、3〜5記事から開始） |
| 共有アクセス時 | URLパラメータ付きアクセスでは結果を即時表示した状態で着地 |

1ページ完結型とし、入力変更に対して結果・グラフをリアルタイム更新する（「計算する」ボタンを待たせない）。

### 6.1 結果カードの構成

- **主役: 最終評価額**（最も大きく表示。共有OGP画像等でもこの数値を主役にする）
- サブ指標: 投資元本合計 / 運用益合計 / 節税額（NISAで◯◯円おトク）

### 6.2 デザイン方針

- トーン: **カジュアルで親しみやすい方向**。金融サイトにありがちな堅い紺色基調ではなく、明るく柔らかい配色・丸みのあるUI・平易な言葉づかい（「非課税保有限度額」には必ず補足説明を添える等）
- ただし数値の信頼性を損なわないよう、結果表示部は可読性・コントラストを最優先（WCAG AA準拠は維持）
- 難しい制度用語はツールチップ・吹き出しでその場解説し、解説ページへ誘導する
- イラスト・アイコンを活用し、初見ユーザーの心理的ハードルを下げる（素材は商用利用可の無料素材またはオリジナル）

## 7. リスクと対応

| リスク | 対応 |
|---|---|
| 計算誤りによる信頼失墜 | 計算仕様の明文化（§3）＋ユニットテスト必須＋金融庁シミュレーターとの突合テスト |
| 金融助言と誤認されるリスク | 免責の常設表示、特定商品への言及禁止をコンテンツ方針として明記 |
| YMYL領域でSEOが伸びない | URL共有・SNS導線を第一の流入経路として設計。SEOは長期施策と位置づける |
| 制度改正 | 定数一元管理（§5.1）。改正時は「◯年◯月時点の制度に基づく」表記を更新 |
