# 解説記事の構成（狙うクエリと記事の対応）

## なぜ記事を足すのか

このサイトは計算ツールが主役だが、SEO 上の問題が2つあった。

1. **索引されるURLが3つしかなかった**（`/` `/guide` `/privacy`）。
   検索の入口が3つでは、どれだけツールの質が高くても流入の上限が決まってしまう。
2. **ツール単体のサイトは「価値の低いコンテンツ」と判定されやすい**。
   AdSense の審査でも同じ理由で落ちやすい。

記事1本 = 索引されるURL1つ。10本追加して sitemap は3件から13件になった。

## 記事とクエリの対応

`src/content/articles.ts` の `targetQuery` に同じものを書いてある。
記事の焦点がぶれたときはここに立ち返る。**1記事1クエリを守ること。**

| slug | 狙うクエリ | 記事タイトル |
|---|---|---|
| `monthly-30000-20years` | 新NISA 月3万円 20年 いくら | 新NISAで月3万円を20年積み立てるといくらになる？ |
| `fill-1800man-fastest` | 新NISA 1800万 何年 最短 | 新NISAの1,800万円枠は最短何年で埋められる？ |
| `sold-quota-recovery` | NISA 売却 枠 復活 いつ | NISAで売却した非課税枠はいつ復活する？ |
| `exit-strategy` | 新NISA 出口戦略 取り崩し | 新NISAの出口戦略：いつ、いくら取り崩すか |
| `tsumitate-vs-growth` | つみたて投資枠 成長投資枠 違い | つみたて投資枠と成長投資枠はどう使い分ける？ |
| `how-much-to-start` | 新NISA いくらから 毎月 | 新NISAは毎月いくらから始めるべき？ |
| `tax-benefit-amount` | NISA 節税効果 いくら | NISAの節税効果は実際いくら？金額で確認する |
| `stop-contributing` | 新NISA 積立 やめる 途中 | 新NISAの積立を途中でやめたらどうなる？ |
| `fear-of-loss` | NISA 元本割れ 怖い | NISAで元本割れが怖い人が確認しておくこと |
| `nisa-vs-ideco` | NISA iDeCo どっち 優先 | NISAとiDeCoはどちらを優先すべき？ |

## 構造

`/guide` をハブ（ピラーページ）、`/guide/[slug]` を個別記事にしている。

- `/guide` は制度全体の解説であると同時に、全記事へのリンク集
- 各記事は `related` で相互にリンクする
- どこからもリンクされていないページはクロールされにくく索引もされないため、
  記事を追加したら必ず `related` にも登場させる

## 記事を追加するときの手順

1. `src/content/articles.ts` の `articles` 配列に追記する
2. `related` に既存記事の slug を2〜3件入れ、**既存記事の `related` にも新記事を足す**
   （片方向リンクだけでは回遊が生まれない）
3. sitemap は自動で増える。手を入れる必要はない

## 書き方

- **`lead` で結論を先に出す。** 検索から来た人は答えを探しに来ている。
  前置きから始まる記事は読まれずに戻られる
- **数字は必ずシミュレーターで再現できる条件とセットで書く。**
  `simulator.query` に同じ条件を入れておくと、読者がその場で試せる
- **制度の数値（1,800万円、20.315% など）は `src/constants/nisa.ts` を正とする。**
  記事本文に書くのは説明のための引用に留め、制度改正時に定数ファイルだけ直せば
  計算結果が正しくなる状態を保つ
- **投資助言にならないようにする。** 特定の商品名・証券会社を推奨しない。
  「必ず増える」「おすすめは○○」といった断定を書かない。
  各記事末尾の免責文はテンプレートで自動的に入る

## 今後の伸ばしどころ

現状の記事は1本あたり1,200〜1,500字程度。これは既存ページ（トップ583字、
`/guide` 853字）の約2倍だが、上位表示を狙うにはまだ薄い。
アクセスが付き始めた記事から、Search Console の実際のクエリを見て
節を足していくのが効率的。最初から全記事を厚くする必要はない。
